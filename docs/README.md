# retro_rt reference

What is true about retro_rt, the shared runtime for the Rust ports of retro
games: the crates, the conventions they share, and how to build a game on
them. Generated by `cargo run -q -p rrt-docs -- index` - edit the pages, not
this file.

Read this first, then the page for the crate you are touching. `status` is the
honesty knob: `solid` means every public item the page covers is documented,
tested and described here as it behaves; `partial` means named gaps remain;
`draft` means written ahead of verification. `covers` names the items a page
describes, and `rrt-docs check` fails when one of them no longer exists.

## Crates at a glance

From each crate's `Cargo.toml`.

| Crate | What it is |
| --- | --- |
| [rrt](crates/rrt.md) | retro_rt in one dependency: the engine loop, the pad, wgpu, audio, discs, networking, pictures and the small shared types (buffers, arenas, fixed point), behind features, with the wgpu, winit and glam versions every game shares. |
| [rrt-app](crates/rrt-app.md) | The engine loop: implement Game, and run() opens the window and the GPU, reads the pad, ticks the game at the console's fixed rate, and presents what it draws. headless() runs the same game with no window, for --shot and tests. |
| [rrt-audio](crates/rrt-audio.md) | Sound out: a game's mixer (anything that renders interleaved stereo i16 at its own rate) played on the default device with cpal, resampled to the device's rate; silent and harmless with no device. |
| [rrt-demo](crates/rrt-demo.md) | The smallest whole game on retro_rt: a pad tester drawn as a 320x240 picture, a tone on Cross, rumble on Circle, --shot for a headless PNG. The template a new game starts from. |
| [rrt-disc](crates/rrt-disc.md) | Game discs: CUE sheets with raw 2352-byte BIN tracks (CD-XA sectors exposed), cooked 2048-byte ISO images (DVDs), and the ISO 9660 file system on either, read from the file without loading it whole. |
| [rrt-docs](crates/rrt-docs.md) | Keeps docs/ honest: regenerates the index from every page's front matter and checks pages against the code - every crate has a page, every item a page covers still exists, no dead links. |
| [rrt-gpu](crates/rrt-gpu.md) | wgpu for retro games: a device with or without a window, offscreen targets read back as pictures, a depth buffer that follows the window, and a presenter that letterboxes a low-resolution picture sharp at 4:3. |
| [rrt-image](crates/rrt-image.md) | Pictures out of a game: a minimal PNG writer for RGBA8, for --shot, dumps and test fixtures. |
| [rrt-input](crates/rrt-input.md) | The host's pad: any gamepad gilrs knows, or the keyboard, read once a frame as a PlayStation-style pad (buttons, byte sticks, analog triggers), and rumble back to it. |
| [rrt-kit](crates/rrt-kit.md) | The small things every port rewrites: buffers recycled across frames (Staging, Pool), a generational arena (Slab), a fixed-capacity history (Ring), reproducible randomness (the era's generators and reductions behind one trait), fixed-point numbers (Q12), a byte reader for file formats, the era's colour formats (PS1/PS2, N64, GameCube, Dreamcast, PSP, Sega, SNES/GBA) with YCbCr and palettes, and BCD. No dependencies. |
| [rrt-macros](crates/rrt-macros.md) | #[rrt::main]: turns `fn main() -> impl IntoGame` into a program that logs, builds the game and runs the loop with the attribute's settings. |
| [rrt-net](crates/rrt-net.md) | Networking for a fixed-tick loop: non-blocking UDP (unicast, broadcast, multicast), TCP client and server with length-prefixed or raw framing, and reliable UDP with unreliable, sequenced, reliable and reliable-ordered channels. Polled once a tick; std only, no async runtime. |
